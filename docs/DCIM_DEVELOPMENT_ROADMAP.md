# 基础管理优先的开发路线（修订版）

本版于 2026-11-09 按正式项目要求修订，不采用 Demo 开发方案。分步实施用于控制依赖和交付风险，不降低功能完整性与生产验收要求。当前顺序以本文为准，1A～3B 表示业务范围与验收归属，不替代下列开发批次。

基础方向：从位置、IP、制造商/供应商、设备模型/组件模型等基础管理开始；权限直接沿用现有角色管理。替代此前“先做设备建档闭环，再补基础管理”的路线。

## 一、统一边界

- 用户关联角色，角色分配菜单、按钮和对应 API 权限。前端控制可见操作，后端继续校验 API 权限。
- 不新增用户数据中心授权，不新增角色数据中心授权，不以 core_scope_grant 作为查询或操作前置。数据中心归属用于业务关系、筛选和统计，不代表额外访问授权。
- 地址空间（VRF/独立路由域）、设备归属、采集探针允许连接的网络范围仍是必要业务/技术约束，不能因取消用户数据范围授权而删除。证据完整性、职责分离、并发排他和状态校验仍保留。
- 基础对象必须有正式管理页面与完整生命周期，不能只提供建档弹窗中的“创建字典”。设备台账只引用已经管理好的基础数据。
- 菜单是业务导航，1A～3B 是业务范围与验收归属，B0～B11 是开发批次；数据库迁移按实际变更独立编号，不与这两套编号机械绑定。已有表不等于对应功能完成。

## 二、业务模块与页面组织

| 一级模块 | 管理对象/独立页面 | 核心关系与规则 |
| --- | --- | --- |
| 位置管理 | 数据中心、楼栋、机房、机柜、库房、货架/库位、临时保管位置 | 支持层级浏览及下级列表；维护名称、归属和各层专属属性。机柜提供 U 位结构；空间归属不得成环，机柜缩容不得切断有效占用 |
| IP 管理 | 地址空间、安全区域、子网、IP 地址池、地址详情及历史 | 明确地址空间与物理位置区别；同地址空间防重复/可分配子网重叠；管理 CIDR、网关、DNS、VLAN、用途、保留地址。空闲/预留/在用/冷却与冲突标记分别展示 |
| 制造商与供应商 | 制造商、供应商/服务商、联系人、资质及有效期 | 原厂与供货/服务方分开；供应商可承担多类服务；联系人、资质归属明确；停用保留历史并阻止新的业务引用 |
| 模型管理 | 设备模型、组件模型 | 均关联制造商。设备模型维护类别、规格、U 高、额定功率、端口/槽位模板、标准组件配置；组件模型维护类型、规格、计量/追踪方式、适配关系 |
| 资产管理（后续） | 设备台账、组件实物、采购/预入库/到货、资产履历 | 引用上述位置、网络、组织、模型；实物身份、供应商、原始组件基线与后续采集版本分别保存 |
| 库存与运维（后续） | 库存、工单、上下架/移机/换件、合同、布线 | 占用与库存动作走业务事务，不能通过编辑基础资料直接修改在用状态 |
| 采集与告警（后续） | collect、SNMP、组件观测版本、告警与外发日志 | 原始证据、清洗、判定、外发分别记录；参考 storage-net，按真实设备验证 |

楼栋、机房和机柜在四层位置树内管理。楼层是机房属性，行和列是机柜属性。货架在仓储模块内管理。

## 三、什么叫“基础管理完成”

每个基础模块必须交付以下能力，适用性在对象规格中明确，不用一个通用 CRUD 表单替代业务规则：

1. 列表/层级浏览、搜索、筛选、稳定分页和详情；详情展示上级关系、引用情况及修改记录。
2. 新增、编辑、启用/停用及可用性规则。无引用、无历史依赖的误建记录才允许删除；有引用时返回阻断原因，保留停用选项。没有启停语义的对象明确采用归档/结束等对应操作。
3. 必填、唯一性、跨字段、父子归属、制造商关联、兼容性及停用引用校验。状态和范围不得只在前端判断。
4. 编辑版本检查、重复提交处理与审计；危险操作确认、失败反馈、并发冲突保留用户输入。
5. 菜单/查询/新增/编辑/启停/删除分别配置角色权限；API 权限必须覆盖所有入口。普通角色允许与拒绝场景都要测试，不只用超级管理员验证。
6. 资产台账和布线按各自需求提供批量能力。位置、IPAM、制造商与供应商的资料通过单条业务操作维护。
7. PostgreSQL 迁移与约束测试、真实 API 集成、真实前端联调通过；已有关联数据的变更必须测试。不得让用户通过 SQL 准备正常业务前置。

模型还需区分：**模型标准配置 ≠ 到货原始组件 ≠ 已确认组件实物 ≠ 正式采集组件**。模型修改使用版本/生效规则，不覆盖已有设备原始基线，也不把当前所有设备改成新模板配置。

## 四、分批实施顺序

| 顺序 | 开发批次 | 验收后才能进入的依赖 |
| --- | --- | --- |
| B0 | 核对当前代码、数据与迁移状态，冻结基础模块字段、接口和角色权限；如发现旧范围授权或台账内字典入口，再按第五节整改 | 统一角色权限行为，原始基线和历史数据不丢失 |
| B1 | 位置管理：数据中心→楼栋→机房→机柜，另有库房与库位；提供正式页面及完整管理 | IP 所属位置、设备位置、库存存放有真实可管理来源 |
| B2 | 制造商/供应商：制造商、供应商/服务商、联系人、资质 | 模型、采购、维保不再依赖临时录入或自由文本归属 |
| B3 | 模型管理：组件模型→设备模型→槽位/端口/标准组件模板及兼容关系 | 设备建档与组件实物有稳定标准；模板修改不会改历史事实 |
| B4 | IP 管理：地址空间/安全区域→子网→地址池与保留规则→历史查询 | IP 可独立规划和管理，后续设备/工单接入分配、预留、释放、冷却事务 |
| B5 | 资产与采购到货：建设设备台账，接入已完整的基础模块；采购、预入库、验收、原始组件 | 采购到货、验收与建档入库闭环；生命周期流转在 B6、报废处置在 B7 完成，不将 B5 通过称为完整资产生命周期交付 |
| B6 | 资产工单：上架、移机、下线、下架、回库，完成审批/执行/验收及自动归档/异常恢复与资源历史 | 空间与 IP 预留、占用、释放/冷却事务一致；采购到货验收随 B5 先交付 |
| B7 | 合同、FRU 与备件维修：合同覆盖、服务团队、库存流水、盘点、领退料、换件、还厂；补齐资产报废与介质处置 | 设备、实物、库存、资质与证据一致；维修人工验收可用，自动健康复核在 B10 联合验收 |
| B8 | 端口与布线：端口实例、跳线、ODF、纤芯、路由、标签与导入；接入资产工单 | 路由可追溯，占用互斥，已确认线路与资产变更一致 |
| B9 | 正式采集：端点、凭据、探针准入、调度、四类任务、主备管理入口、观测与组件差异历史 | 实机能力、任务可靠性、时序容量通过；采集不覆盖原始基线 |
| B10 | Trap/MIB、告警、维护窗口、企业微信/短信/Webhook 与外发日志，接入维修复核 | 来源、归并、恢复证据、通知回执与工单闭环可追溯 |
| B11 | SAN 拓扑与分析，再扩展存储厂商及 NAS/对象资源 | 配置与映射有来源，物理逻辑对账及影响分析联合验收，未知不判成功 |

B2 完成制造商、供应商、联系人和资质的完整基础管理，B7 复用这些档案实施合同绑定、服务团队与维修/处置资质核验，不另建第二套档案。

归档是验收成功后的自动结果，不另设人工归档步骤：验收事务校验全部必需子项、证据和当前版本，通过后将工单置为 `completed`（已完成并归档），同时写入 `completed_at`、验收动作及审计。事务失败仍保留原状态；归档后不允许普通编辑或重新打开，纠错通过关联更正工单追加记录。

B2 可与 B1 并行；B3 依赖制造商，B4 依赖位置/安全区域关系确定。IP 与位置同为基础模块，B4 排在此处是依赖和排期顺序，不是降低其重要性。机柜占用、地址分配/释放的数据库不变量在基础阶段确定，依赖真实设备/工单的动作在 B5/B6 验收；基础阶段不伪造设备绑定以展示成功。

B7 与 B8 在资产/工单契约稳定后可独立推进；B9 的设备适配和网络可行性可提前验证，但正式集成依赖资产/系统身份和生命周期接口。B10 依赖采集事件与维修契约，B11 的逻辑路径依赖采集，物理对账依赖 B8，故障影响依赖 B10。允许并行不等于省略依赖验收。

每批交付包含数据库迁移、领域规则、Service/API、页面、角色权限、异常恢复、测试与说明；按需求记录基础验收、联合验收、实机/生产验证及未覆盖项。不得以演示成功替代正式验收。

## 五、当前状态与历史实现处理

位置、IP、制造商与供应商后端已接入现有角色授权与版本化迁移。接口范围、权限及与资产工单的边界见 [基础管理 API](DCIM_MANAGEMENT_API.md)。此批次交付后端，页面和生产联合验收仍待后续推进。以下保留历史实现的处理规则。

| 待核对的历史实现 | 处理规则 |
| --- | --- |
| 设备台账“新增范围授权”及 scope-grants、逐用户数据中心过滤 | 撤除，不迁移为另一套角色数据范围；代码、权限种子、OpenAPI、测试及文档同步清理 |
| 台账里的“维护前置字典”及四类简单创建接口 | 拆回所属正式模块；可复用持久化和校验代码，但补全编辑、启停、引用、详情及角色权限，不能只搬动弹窗 |
| 已有设备、原始组件基线、附件、版本/幂等/审计 | 保留数据与有效实现，按新角色规则改造并回归；暂缓继续扩大设备流程 |
| 共享资源身份、设备/位置归属、地址空间、证据关联 | 保留业务语义；不再因保留归属字段而继续执行用户中心授权 |
| 已登记迁移与历史记录 | 先确认是否已应用；已应用环境采用新增迁移，不删除台账、不强制重建库、不丢弃历史 |
| 已有 D1 测试与说明 | 作为历史开发记录；其通过只证明当时实现，不代表新路线验收。替换范围授权预期，新增普通角色正反例 |

历史 scope 表是否存在或被使用，须核对目标环境的迁移和代码。

## 六、下一批明确任务

基础管理后端已覆盖 B1、B2 和 B4 的档案、地址池和权限。后续按实际排期建设设备与组件模型、基础管理页面，以及依赖资产和工单的资源占用联动。

各模块按完整业务交付，统一字段、接口、路由和迁移契约，不让前后端各自猜测字段。共享能力复用现有平台；每批开始前落实对应字段字典、API 和验收用例，不要求一次性实现全部领域表。

需求决定功能与规则，本文决定实施顺序，领域模型约束数据关系。三者变更应同步。
