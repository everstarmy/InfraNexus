# DataTable 详细强化方案

日期：2026-10-27。状态：设计稿；M0 已完成，阶段证据见 [M0 验收记录](M0_VALIDATION.md)。

关联：[任务清单](TODOLIST.md) · [目录说明与授权边界](README.md) · [历史验收](../DATA_TABLE_IMPLEMENTATION.md)。

## 1. 目标与边界

建设可覆盖后台管理复杂列表场景的通用表格：支持可控滚动、灵活查询、工作视图、可靠批量操作以及按需启用的复杂数据能力。保持当前页面兼容，避免一次性重写。

初始规划仅交付文档，后续用户已授权实施 M0。实施按阶段形成独立可验收结果，不把全部高级能力当作基础表格上线前提。新能力默认显式开启，未接入后端的功能不展示虚假的全量语义。

遵循项目已有约束：React 19、Base UI、Tailwind v4、强类型列定义、语义主题、移动端布局、权限控制、统一反馈；业务增强不修改 `components/ui/` 原子组件。后端遵循 Handler → Service → Repository、参数白名单、统一响应与安全日志规则。

不在本方案中建设公式引擎、透视分析平台、多人协同编辑、通用报表设计器或完整电子表格替代品。共享视图、云端同步、无限滚动列为后续候选，不纳入首轮必交范围。

## 3. 总体设计

### 3.1 组件职责

保持 DataTable 为业务入口，逐步将复杂状态协调拆为专用 Hook 与纯函数。按实际需要新增以下模块，不提前建立空抽象：

| 模块 | 职责 |
|---|---|
| viewport / layout | 高度、唯一主滚动容器、固定偏移、尺寸观察、全屏 |
| query-state | 查询归一化、受控状态、URL 编解码、查询指纹 |
| column-preferences | 显隐、顺序、宽度、固定、密度、版本迁移 |
| saved-views | 命名视图、本地存储、应用/更新/删除/默认视图 |
| selection | 当前页、跨页 ID、全部匹配三种语义及作用域失效 |
| filter-builder | 类型化筛选编辑器与表达式展示 |
| export / editing adapters | 调用业务提供的导出、更新能力，不内置业务 API |

表格管理交互与展示；页面管理权限、查询请求和业务操作；服务端管理数据权限、全量查询、批量执行和一致性。不得把用户/角色/LDAP 专用逻辑写入表格核心。

### 3.2 状态与能力契约

- 新增能力使用分组配置，例如 `viewport`、`density`、`selection`、`views`、`export`，避免继续平铺大量互相矛盾的布尔参数。
- 数据模式采用明确的客户端/服务端能力说明。已使用 `serverFiltering/serverSorting/serverPagination` 的页面通过兼容层继续工作，按页面迁移后再讨论废弃。
- 每类状态只允许一个权威来源：受控值优先；不允许内部状态、URL 和父组件相互写回形成循环。
- 恢复优先级：页面受控值 > 有效 URL 查询覆盖项 > 已选/默认命名视图 > 已保存布局偏好 > 页面默认值。查询与布局分别合并；应用视图作为明确操作通知父组件。
- 关键行操作使用稳定 ID。现有 `batchActions(rows, reset)` 保留当前页语义，新跨页操作通过独立描述符传递，不伪造未加载行对象。
- 各列通过强类型 meta 声明显示、排序/筛选能力、编辑器、导出值、隐藏/固定/排序约束；数据字段、显示列 ID、后端查询键明确映射。
- TanStack 版本以仓库安装版本为准；不能直接套用其他主版本 API。没有证明必要性前不引入新表格框架或依赖。

## 4. 阶段一：滚动与布局（M1）

### 4.1 高度模型

提供三个互斥模式，建议配置语义如下（不是已实现 API）：

| 模式 | 行为 | 使用场景 |
|---|---|---|
| `content` | 按内容自然增长，保持旧默认行为 | 短列表、嵌入内容 |
| `max-height` | 数据视口不超过给定 CSS 长度，少量数据自然收缩 | 常规业务列表 |
| `fill` | 占用父布局剩余空间；父级需明确高度并允许子级收缩 | 全屏工作台、固定外壳 |

`maxHeight` 指表头和表体所在的数据视口上限，不包含工具栏、分页。组件总高度因此可能大于该值；文档及命名必须明确。`fill` 则约束整个组件，在扣除工具栏、分页后分配数据视口高度。

不在每个页面复制不同的魔法 `calc(100vh - Xpx)`。优先用父级 flex/grid、`min-h-0` 和可测量尺寸适配标题、筛选换行。高度不足时允许外层自然滚动，不能挤掉关键控件。移动端默认采用 content 或适度最大高度，具体通过触摸验证决定。

### 4.2 单一滚动视口

组件结构为：工具栏 → 数据视口（table/thead/tbody）→ 汇总或状态区 → 分页。数据视口统一承担水平和垂直滚动。

现有原子 Table 已包含横向滚动容器。优先由 DataTable 局部包装样式作用于该容器，必要时新增 DataTable 自有语义 table 包装。不得通过在外层再套 `overflow-auto` 留下两个抢占滚动或 sticky 参照系的容器；不得修改共享 UI 原子组件满足业务需求。

- 纵向固定表头，左右固定单元格；交叉处表头固定单元格层级最高。
- 固定区域使用不透明主题背景，hover/selection 与普通单元格一致。
- 多行分组表头按累计高度计算 top 偏移；未实现前不宣称支持分组表头吸顶。
- 分页不进入数据视口；工具栏换行不覆盖首行。
- 水平溢出才显示阴影/额外滚动控制；无溢出不制造空白条。
- 如提供同步滚动条，数据视口是权威来源，同步需防反馈循环；列显隐、拖宽、窗口变化时重新计算。
- 骨架和空状态遵守高度约束，无横向内容时不保留旧溢出提示。

### 4.3 滚动恢复、密度和文本

| 触发 | 纵向位置 | 横向位置 |
|---|---|---|
| 翻页/改变页大小 | 回到顶部 | 保留并裁剪合法范围 |
| 查询或排序正式生效 | 回到顶部 | 尽量保留 |
| 同一查询后台刷新 | 优先保留可见行锚点，缺失时裁剪位置 | 保留 |
| 切换保存视图 | 回顶部 | 回起点 |
| 返回列表 | 查询一致且有缓存时恢复；无数据时等待布局稳定 | 合法范围恢复 |

提供紧凑/标准/宽松密度，集中设置行间距和字体相关 token，触摸目标不可随密度缩小至难以操作。文本列支持单行截断、多行限制、完整换行；完整内容通过可聚焦触发器或详情查看，不能只依赖 hover。操作列与选择列尺寸独立。

全屏采用页面内扩展模式优先，复用 Base UI 处理需要的浮层焦点语义。退出后恢复焦点、查询和滚动，覆盖 ESC、嵌套菜单及移动端视口变化。

M1 验收：多行数据仅在数据视口内滚动，表头/工具栏/分页行为正确；少行不被强制撑满；content 兼容旧页面；左右固定、加载、空表和移动端不破坏布局。

## 5. 阶段二：列配置、查询和视图（M2）

### 5.1 列布局

- 拖拽调整列顺序，同时提供“前移/后移”键盘等价操作；选择列与操作列可锁定位置。
- 支持多个业务固定列时，设置最小中间可用宽度预算；超过预算时提示或临时减少固定，不能覆盖全表。不将响应式降级结果写回用户偏好。
- 列宽按可见/已加载样本适配，明确不是全量扫描；设置 min/max、测量上限并处理图标/自定义 cell。保留手动调宽和恢复默认。
- 分组表头显隐、拖动边界与固定采用一致规则；无法跨组移动时禁用并说明。
- 列设置在窄屏可采用现有 Sheet/Drawer 包装，并保证配置连续操作不意外关闭。

### 5.2 查询模型

统一描述字段 ID、类型、允许操作符、可选项来源和后端字段映射。

| 类型 | 操作符示例 | 关键语义 |
|---|---|---|
| 文本 | 包含、等于、前缀、为空 | 大小写、空字符串与 NULL 分开约定 |
| 数字 | 等于、大于、小于、区间 | 精度、边界包含、非法输入 |
| 日期/时间 | 之前、之后、区间、近 N 天 | 时区、自然日与时间点区分 |
| 枚举 | 属于、不属于 | 空集合不等于全选 |
| 布尔 | 是、否、未设置 | 允许三态的字段单独声明 |

高级筛选采用可版本化表达式树：条件节点与 AND/OR 分组节点。第一版建议最大深度 3、总条件数 20，前后端一致限制，后续根据性能调整。界面提供字段、操作符、值编辑和可移除摘要；没有服务端能力时不能仅过滤当前页并宣称全量查询。

多列排序展示优先级，建议上限 3 个字段；服务端补稳定唯一键作为兜底排序，确保同值分页可预测。权限范围必须与整个筛选表达式以 AND 组合，不能被 OR 条件绕过。

中文输入法组合期间不发送中间查询；输入完成后按约定防抖，Enter 可立即提交。新查询取消旧请求或忽略过期结果；筛选变化与页码归零作为一次状态转换，避免重复请求。日期过滤按用户时区转换为明确区间，推荐服务端半开区间 `[start, end)`，迁移时验证旧边界语义。

### 5.3 URL 与命名视图

- 复用现有 URL 工具，新增版本与字段/操作符校验；保留无关路由参数和多表前缀。
- 未知字段、已删除列和非法值安全降级并提示；不能无提示地执行完全不同的高风险批量范围。
- URL 不保存敏感筛选值、选择集合、编辑草稿；设置长度预算，复杂条件超限不生成不可用链接。
- 本地命名视图保存 query、sorting、列布局、密度；不保存选中 ID、分页页码或滚动坐标。页大小可作为显示偏好保存。
- 支持新建、另存为、覆盖、重命名、删除、设为默认、未保存修改提示、恢复页面默认。
- 默认按用户/表格/schema 隔离存储，处理损坏 JSON、存储禁用、容量不足与多标签页更新；失败不影响查询。
- 列 ID 增删、字段权限变化通过白名单迁移，至少保留一个可见业务列。退出或换用户时清除内存态，存储隔离不等于权限校验。
- 云同步、团队共享视图不属于 M2 必交项，若实施需独立解决所有权和字段权限。

M2 验收：前后端得到相同查询语义；恢复视图不重复请求；多列排序跨页正确；非法状态不会破坏页面；现有 URL 和布局偏好可迁移。

## 6. 阶段三：跨页选择、批量处理与导出（M3）

### 6.1 选择表达式

新选择模型为判别联合：

- `page`：仅当前页，兼容现有行对象回调。
- `ids`：明确 ID 集合，跨分页保留；选择摘要显示总数和当前页数量。
- `allMatching`：规范化查询条件/查询凭证 + 排除 ID 集合，不向浏览器加载全部 ID。

必须配置稳定行 ID 和选择作用域。查询指纹包含资源类型、搜索、筛选、固定业务范围（如部门和含下级）及权限上下文版本；不包含页码、页大小、列布局和排序。指纹仅辅助一致性，不作为服务端权限凭证。

规则：同一作用域分页/排序保留跨页选择，筛选/部门范围/身份变化清空并提示；禁用行不能被全选混入。ID 集合和排除集合有明确大小上限，达到上限时说明，不静默丢失。

“全部匹配”第一版采用执行时重查语义：预览数量可能变化，确认时说明；服务端重新校验范围、行权限和业务状态。需要精确快照的业务另行设计快照凭证，不承诺列表点击瞬间的数据冻结。

### 6.2 批量契约

- 预检返回可执行、不可执行及原因计数；危险操作使用现有 useConfirm。
- 执行请求明确 action、selection、业务参数和幂等语义；不得将任意 SQL/客户端权限传入仓储。
- 返回 success/failed/skipped 计数和受限的失败明细，明细过大提供分页或按需查询。
- 每个业务动作明确事务性：全部原子成功或允许部分成功，前端不能统一假设。
- 自动重试只适用于幂等操作；“重试失败项”只提交可重试失败 ID，不能重复成功项。
- 关闭页面后的任务处理规则取决于执行模式。小批量同步；只有性能证据显示必要时才扩展现有任务机制，不默认建设通用任务中心。

### 6.3 导出与复制

- 导出范围：当前页、显式已选 ID、全部筛选结果；显示预估条数与权限限制。
- 导出字段独立白名单；区分展示文案与原始值，明确日期时区、枚举映射、数字精度、空值和列顺序。
- 当前页导出可前端执行；全量/跨页必须走受授权的服务端查询，不能靠循环翻页无上限抓取。
- 首批建议 CSV；只有明确格式化需求才增加 XLSX。防护公式注入，验证分隔符、双引号、换行、编码及危险前导字符。
- 服务端导出需条数/资源预算、取消或超时、临时结果过期与下载鉴权；若需要异步处理，明确任务归属和失败恢复。
- 复制支持单元格和已加载行 TSV；完整未加载数据不假装已经复制。处理 Clipboard 失败并用 notify 反馈。

M3 验收：跨页选择与实际执行范围一致；权限变化不能扩大结果；批量部分失败可解释并可安全重试；导出范围、行数、字段、顺序和转义符合约定。

## 7. 阶段四：复杂数据与编辑（M4，按场景启用）

### 7.1 展开、树形与聚合

- 普通详情展开与树节点展开使用独立状态；详情按需加载、缓存、重试，关闭后不持有失效请求引用。
- 树形分页第一版明确按根节点分页；子节点不占根分页计数。筛选是否保留祖先由业务契约决定，默认保留匹配路径。
- 懒加载子节点区分“未加载/加载中/空/失败”，服务端返回是否还有子节点；展开状态按稳定 ID 保存。
- 分组和聚合明确当前页/客户端全量/服务端全量的计算范围。服务端全量汇总必须使用与列表相同的权限及筛选。
- 汇总行不参与普通数据选择和行操作；金额精度、空值、单位及计数口径显式声明。

### 7.2 行内编辑

- 第一版以单行编辑/保存为主，字段白名单与 can 权限共同控制；不默认开放所有单元格。
- 提供校验、保存、取消、pending 与失败反馈；键盘 Enter/ESC 行为不干扰输入法或多行输入。
- 翻页、切视图、关闭详情和离开页面时处理未保存草稿；不能无提示丢失。
- 更新使用版本号或等价乐观并发检查，冲突返回最新状态及可理解提示；不静默覆盖其他人的修改。
- 成功更新缓存，失败保留草稿或回滚显示；自动保存、批量粘贴编辑另行评估。

### 7.3 实时变化

复用已存在的刷新/事件来源，显示有新数据或行已变化；用户选择、编辑或定位期间不自动重排。采用“有更新，点击刷新”作为默认策略，刷新时按选择作用域规则核对已选 ID。

M4 验收：树计数与分页语义一致；汇总不误标为全量；编辑冲突不丢用户输入；实时变更不打断正在进行的操作。

## 8. 性能与虚拟化（M5，证据驱动）

优先维持分页并减少无意义渲染。行虚拟化只用于需要同时展示大量行的场景，列虚拟化只用于真实宽列场景，不默认让所有表格承担其复杂性。

基准样本建议：常规 100 行 × 20 列、大客户端列表 10,000 行 × 20 列、宽表 100 行 × 100 列、树形 5,000 节点。明确数据是本地模拟还是真实服务端数据，性能结论不可互相替代。

先记录机器、浏览器、构建模式、样本、测试次数及基线，再冻结阶段预算。候选目标：常规表格重复排序/选择/视图切换 p95 可见响应不超过 200ms；虚拟场景渲染节点数量随视口及 overscan 有界增长；重复挂载卸载不持续积累监听器和缓存。候选值未经测量不能写成已达标承诺。

虚拟化必须验证动态行高、展开行、固定列、表头、滚动恢复、焦点与屏幕阅读器；无法兼容的组合需显式禁用并给替代模式。列虚拟化是否实施由 M5 测量决定，暂缓时登记依据，不影响前面阶段验收。

## 9. 前后端协作与兼容迁移

| 能力 | 前端工作 | 后端工作 |
|---|---|---|
| 滚动/密度/列布局 | 组件和页面布局 | 无 |
| 本地保存视图 | 版本化存储与恢复 | 无 |
| 高级筛选/多排序 | 编辑器、序列化、能力声明 | 类型校验、字段白名单、绑定参数、稳定排序 |
| 全量选择/批量 | 选择描述符、确认、结果展示 | 权限重查、上限、事务/幂等、失败明细 |
| 全量导出 | 范围/字段选择与状态展示 | 同查询权限、资源预算、文件与下载权限 |
| 懒加载树/全量聚合 | 查询状态和展示 | 节点/统计接口及口径 |
| 行内编辑 | 草稿、校验和冲突展示 | 更新白名单、版本冲突检测 |

不在本设计稿虚构已经存在的接口地址。M0/M2/M3 开始时形成实际请求/响应契约，标注已有接口可复用部分和新增部分。后端过滤组合必须参数化，SQLite/PostgreSQL 都需要真实兼容验证。

迁移顺序：独立测试夹具 → 用户列表 → 角色列表 → 部门成员 → 权限树 → LDAP 配置/日志/预览。页面只启用适合自身的能力：权限树不强行启用平面列表的批量/聚合；弹窗预览单独验证高度和焦点；LDAP 日志优先只读能力。

每阶段保持旧参数兼容和功能开关，可单页回退。偏好迁移保留版本信息，不覆盖无法识别的原始存储；回退版本能安全使用默认配置。没有对应后端能力时隐藏入口，不做“假成功”。

## 10. 验证与交付标准

### 10.1 功能组合

必须覆盖：最大高度 × 左右固定 × 调宽；视图恢复 × URL × 受控查询；跨页选择 × 筛选变化 × 权限变化；空表/错误 × 保留工具栏；树展开 × 分页；编辑 × 刷新；虚拟化 × 动态高度/焦点。

视口覆盖至少 375/390、768、1280/1440、1920；超宽回归复用现有用例。明暗主题、200% 缩放、键盘和触摸操作纳入验收。浏览器覆盖 Chromium/Firefox/WebKit；未具备环境的项目明确记为未覆盖，不能将 Skip 计为通过。

### 10.2 测试层级

- 单元：查询归一化、URL、偏好迁移、选择状态机、日期边界、导出转义、编辑冲突转换。
- 组件/浏览器：布局实测、scrollTop/scrollLeft、固定交叉层、菜单与焦点、输入法、空状态和异常恢复。
- 接口集成：真实服务端筛选/排序、权限范围、批量执行/重试、导出计数、并发编辑、SQLite/PostgreSQL；mock 测试不能代替这些结果。
- 性能：生产构建、固定夹具、记录环境与分位值，区分前端渲染和数据库查询耗时。

前端标准检查：在 frontend 目录运行 `npm run lint`、`npm test`、`npm run build`，按阶段运行相关 Playwright 用例。后端行为修改按项目要求执行相应测试、`go test -race ./...`、`go vet ./...`；缺环境记录未覆盖。纯文档阶段检查相对链接、任务对应和 `git diff --check`，不声称运行过行为测试。

### 10.3 阶段完成条件

每阶段必须同时具备：实际接口说明、组件实现、试点与计划页面迁移、必要回归证据、已知限制、回退办法、任务清单更新。截图证明外观，交互断言证明行为；二者不能互相代替。

## 11. 推荐实施顺序与决策点

| 阶段 | 交付物 | 依赖/决策 |
|---|---|---|
| M0 基线与契约 | 场景矩阵、状态约定、测试夹具 | 核对实际源码及用户未提交修改 |
| M1 滚动布局 | 高度/表头/滚动、密度、文本、全屏 | 不依赖新后端接口 |
| M2 查询视图 | 列顺序、类型化筛选、多排序、本地视图 | 服务端查询扩展先定契约 |
| M3 批量导出 | 跨页选择、全量选择、批量结果、导出 | M2 查询模型；业务权限与执行语义 |
| M4 复杂业务 | 树/详情/聚合、行编辑、实时提示 | 指定试点页面与对应业务接口 |
| M5 性能强化 | 性能报告、必要的虚拟化与降级 | 测量证明必要性及兼容组合 |
| M6 收口 | 全页面能力矩阵、回归、使用文档 | 所有纳入交付的阶段完成 |

M1 可先独立上线；M2 的本地布局/视图与后端高级查询分别验收；M3 不在后端未就绪时开放全量入口；M4/M5 按实际场景启用，不要求每张表拥有全部能力。
