# DataTable 功能、样式与互操作性优化方案

## 1. 目标与范围

本方案根据当前组件源码核对外部审查意见，基线提交为 `4aa83b1`。核对方式是静态代码检查，不代表所有场景已在浏览器中复现。方案编写时只授权文档；后续用户已授权按方案优化代码，当前按批次推进。

目标是让数据优先、查询状态一致、组合配置可靠、复杂操作可发现。维持默认两行工具栏、选择后显示批量操作、低频操作收入菜单，不恢复通用复制按钮、横向滚动说明条或重复页汇总。

优先修复现有能力的组合问题。服务端查询、权限、批量执行、导出和编辑事务仍由业务负责；不新增后端模块、共享视图、列虚拟化或通用表格编辑器。

## 3. 统一状态与接口原则

以下接口名称是设计草案，并非已实现 API；落地前检查现有调用点和类型兼容性。

1. 每类状态只有一个拥有者。普通客户端表格由内部状态管理；受控查询由宿主拥有，组件通过明确回调发出下一份状态。
2. 高级查询不得与另一份隐式搜索、筛选、排序状态互相覆盖。允许并存的条件须定义为明确的组合，并共同参与空态判断与重置。
3. 显示偏好不改变查询权限。列隐藏不取消排序；取消排序应有显式操作。
4. 查询变化必须同步处理页码、选择范围和滚动位置；不靠多个互相覆盖的 URL 写入完成事务。
5. 不改变现有默认语义的配置可增量接入；破坏性接口变更需列迁移步骤，不以静默回退掩盖错误。

## 4. 查询功能整改设计

### 4.1 输入草稿与应用值分离

日期和数字编辑中保存原始字符串，允许暂时不完整的输入。点击“应用查询”时统一校验；非法字段原地显示错误、保持草稿并聚焦首个错误，不发送请求。

日期输入明确采用带偏移的时间值，或通过显式本地日期时间控件转换。日期区间的时区、日末边界及半开区间由宿主定义。带时区值规范化成 UTC 时验证同一时刻不变；不接受含糊的浏览器自动解析作为接口契约。失焦可以显示校验信息，但不强制改写尚在编辑的文本。

枚举 in 复用可访问的勾选列表交互，支持搜索、全清和选中计数，保留 string/number 原始类型；不把所有枚举值强制变成字符串。空集合行为与解析器一致，不暗中解释成全选。

### 4.2 查询状态、空态与重置

提取统一的查询活动状态，至少覆盖普通搜索、离散筛选、受控日期、高级 search/filter。排序属于排序状态，不单独把空表判为“筛选无匹配”。

“重置筛选”清除搜索、日期、离散和高级过滤，页码归零；默认保留排序与布局。另提供菜单内的“清除排序”，不增加常驻按钮。受控模式通过宿主一次性应用下一份查询和页码，保证 URL、请求缓存键、选择 scope 同步。

### 4.3 多排序交互

单排序模式保持现有操作。多排序模式中，修改已参与排序列的方向保留其他列与优先级；新增排序字段提供明确的“追加排序”操作，最多三列。清除单列只移除该字段。

表头显示简洁序号；完整顺序在“更多”内显示，即使排序列隐藏也可查看和删除。高级编辑器与表头统一写入同一排序数组，避免各维护一份。

### 4.4 受控日期与页大小

建议增加 `externalDateRange` 配置（value/onChange/title），同时保留 dateRangeKey 的客户端模式。受控配置生效时不再偷偷修改客户端日期列筛选；无对应列也允许服务端筛选。重置、空态、URL 由统一查询协调层接入。

页大小合法值从同一份配置传入分页、视图编解码和 URL 解析，默认仍为 10/20/50/100。宿主进一步受服务端最大页大小约束。恢复不再支持的历史页大小时回退到明确默认值并提示，不因一个页大小导致全部视图无法读取。虚拟化兼容模式的页大小上限单独保留，不能被普通配置绕过。

## 5. 表格视觉与布局整改设计

### 5.1 统一固定列几何

将 stickyActionColumn 作为固定列模型的兼容入口：actions 存在且可见时，把它规范化为最末尾 end 固定列；去重并消除 start/end 冲突。所有固定单元格和表头共用同一套宽度、顺序、偏移和窄屏预算，不混用 right-0 与独立 end 偏移。

边界样式施加在“实际仍固定”的最后一个左列、最前一个右列，而非每列都画阴影；窄屏降级后同时去除对应样式。继续验证 grouped header、RTL 逻辑方向、列隐藏、拖宽和详情辅助列。

### 5.2 详情与分组

分组标题使用视口可见宽度，横向滚动时仍可识别分组。详情默认在视口宽度内换行，内部宽内容由详情自己的滚动容器处理。保留表格语义与 colSpan，不把整行绝对定位；对确需整表宽度的详情提供明确选择，避免破坏既有详情布局。

### 5.3 密度、骨架与文本

使用组件范围内的密度变量统一正文内边距、骨架、表尾和辅助控件；表头可维持稳定紧凑高度，不要求机械等比缩放。触屏目标尺寸优先于密度，复选框通过命中区扩大而不是把图形拉长。

骨架复用可见列 ID、实际列宽、辅助列和固定位置；首次未知数据时不能保证零高度变化，但加载前后列边界应稳定。后台刷新继续展示已有行，不切换整表骨架。

虚拟行高在未显式传 estimateRowHeight 时按密度提供合理估算，显式值始终优先；动态测量仍是最终依据。密度切换需刷新测量并按稳定 ID 恢复锚点，保持焦点和末行可达。

文本仅在实际溢出时提供全文入口。检测覆盖列调宽、字体加载、密度变化和虚拟行重挂载；不要为每个不可见单元格建立观察器。键盘聚焦也能发现全文入口；普通短文本保持可选择，拖选不打开浮层或行详情。

### 5.4 自动调宽

保持有界采样，不扫描全量远端记录。优先支持显式文本测量回调，其次使用原始标量；图标、标签、按钮预留可解释的附加宽度。若采样已挂载 DOM，仅测量真实内容宽度，不能直接用撑满整列的外框宽度。限制 min/max，不适配固定辅助列，不为测量临时挂载全量行。

## 6. 互操作性整改设计

### 6.1 统一选择操作区

增加一个可选的受控“选择操作区”契约，宿主提供总选择数量、当前页数量、选择类型、清空回调、可选的全匹配入口与业务操作内容。组件只管理展示位置和可访问性，不获取全量 ID、不推测 allMatching 的准确记录集合。

优先级：显式选择操作区高于旧 batchActions；同一时刻只渲染一个。未选中时显示标题及常用操作，选中时在同一区域替换标题；导出未选中数据仍是独立低频操作。超过客户端集合上限、请求进行中、身份/权限/查询变化的处理继续由现有宿主逻辑保障。

跨页选择数与已加载行数不得混用。服务端全匹配数量标注其估算属性；执行时仍预检并确认，不把前端选择数量当作执行授权。

### 6.2 保存视图身份

宿主在真正应用视图时同时提供 activeViewId 和对应基准快照。菜单据此初始化选中态和“已修改”，而不是无条件选中默认视图。URL 优先覆盖默认视图时不冒认当前视图。

建立规范比较规则：对象键顺序不影响相等，排序数组顺序必须影响相等。重命名保留 ID，删除清空活跃身份，用户/表格/schema 切换重置上下文；保留跨标签页冲突检测和敏感字段验证。

### 6.3 全屏生命周期

先建立生命周期测试，记录切换前后挂载次数、局部输入草稿、IME、焦点和虚拟测量。优先验证稳定挂载容器配合 Base UI 官方支持的 Portal/容器机制；不能假设改变 createPortal 目标会自动保留子树。

不得直接移动 React 管理的 DOM，也不以普通 fixed 容器替代 Dialog 的焦点约束、背景隔离和 Escape 行为。若可靠方案需要较大架构变更，独立实施；在此之前维持已公开的“局部草稿外置”契约，不宣称无重挂载。

### 6.4 元数据与内部拆分

仅在多个页面确有重复时增加纯提取函数，支持明确覆盖优先级、重复 key 检测、不可导出列排除。query/export/edit 的权限和服务端允许字段仍由宿主显式声明；不根据 UI 标签或元数据自动开放能力。

建议提取顺序：固定列几何纯函数 → 查询状态及重置计算 → 偏好存储 Hook → 选择列辅助模块。保留现有公开导出，先测试再迁移；不要同时重写渲染、持久化和请求层。
