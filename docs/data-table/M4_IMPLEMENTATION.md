# M4：复杂数据与编辑接入

日期：2026-10-29。基线为 M3 提交 `b062db7`。本阶段按用户授权实施，试点为用户列表与权限清单，不新增独立业务模块。

## 用户列表

### 独立详情

`DataTable.detail.render(row)` 在独立详情行渲染内容；一次打开一行，状态与树节点 expanded 分离。详情行不进入数据选择、分页计数和行操作。查询作用域改变时收起详情。

用户列表通过 `UserRowDetail` 按需调用已有 GET `/users/:id`，消费 AbortSignal；关闭后组件卸载，未完成请求可取消。React Query 缓存按操作者和用户 ID 隔离，30 秒新鲜期、60 秒闲置回收，失败提供显式重试；权限不足不展示入口。编辑成功同步行详情和已有侧栏详情缓存。

### 当前页分组与汇总

`groupBy: { label, key }` 将已加载的当前页平面行按字段分组，组头显示当前页组数量；`summary: { label, render }` 将当前渲染行交给纯展示汇总。组头、详情、汇总不作为普通数据行，不参与选择。Shift 连选遵循分组后的视觉顺序。树形表启用 getSubRows 时不应用平面分组，避免拆散父子路径。

用户列表提供“按来源分组（当前页）”，以及当前页人数、启用人数、停用人数。没有服务端全量汇总、金额或任意字段求和；计数只使用安全整数，不把 NULL 当作金额零，也不把页内统计标为全量。后续如增加金额聚合，需要业务明确最小货币单位和精度规则。

### 昵称草稿与 CAS

复用现有白名单资料更新接口 PUT `/users/:id`，本轮试点仅提交 nickname 和 expected_revision。只允许本地、非内置、具有 users:update 权限的用户行进入编辑；接口仍执行服务端白名单、授权和版本检查。

草稿由 `UserInlineEditProvider` 保存在页面内存中，按用户 ID 隔离，记录值和开始编辑时的资料版本。翻页、排序、筛选、切换视图、全屏及单元格卸载均不删除草稿；顶部提示未结束的编辑，返回该行可继续。离开页面和关闭浏览器复用现有 UnsavedChangesProvider；没有本地持久化或跨会话恢复。

- Enter 显式保存、Escape 取消；输入法 composing 时不触发保存/取消；Tab 只移动焦点，不再自动保存。
- 执行中保存、取消及放弃全部按钮禁用；pending 保存在草稿中，行卸载再挂载也不能重复提交。
- 校验或网络失败保留草稿；权限变化后显示原因并禁止保存，仍可取消。
- 409 保留原草稿和原版本，保存暂时禁用；“重新加载并核对最新版本”读取最新安全 DTO，提示最新昵称并更新比较版本。之后仍需显式保存；不会静默覆盖新版本。
- 保存成功同步已缓存的相关用户列表及详情，只移除对应草稿。一次请求只保存一行；无批量粘贴、自动保存或多字段通用编辑器。

### 后台变化

`useDeferredTableData` 在有选择或编辑草稿时保留显示快照，复用现有 React Query/SSE 失效与刷新机制。新数据到达后显示“有新数据，点击更新表格”；确认后才替换显示数据，草稿不变。新查询范围/新页始终显示自己的数据，不把分页占位数据固定为快照。版本保护仍由服务端 CAS 执行。

## 权限树按需浏览

权限清单保留原完整树管理入口，新增可切换的只读“按需浏览权限节点”。新模式使用 GET `/api/v1/permissions/nodes`，需要该 API 权限。接口与完整权限树相同地受 Casbin 控制，不新增公开读取路径。

请求参数：可选 parent_id、keyword，page（1..100000）、page_size（1..100，默认 50）。响应为标准 Envelope，data 包含：

| 字段 | 语义 |
| --- | --- |
| items | 当前层当前页；不携带后代，包含 has_children |
| total | 当前 parent 的筛选后直接子节点数量；未指定 parent 时为根数量 |
| root_total | 筛选后根节点数量 |
| matched_nodes | 自身名称、编码或路径直接匹配关键词的节点数量 |
| retained_nodes | 直接匹配节点及保留祖先的总数量 |
| page / page_size | 当前层分页参数 |

筛选是大小写不敏感的字面子串匹配。保留匹配路径的祖先；父节点自身匹配不自动纳入所有不匹配后代。has_children 反映同一筛选后的树，叶节点查询返回空 items；不在过滤后树中的 parent 返回 404。排序固定为 sort_order、created_at、id。

根节点分页，展开子节点不消耗根分页槽位。客户端子层以 100 条分页读取，单父节点最多加载 500 条；超限明确报错并要求缩小查询，不静默截断。未加载、加载中、已加载为空和失败状态明确，失败可重试；折叠取消该节点未完成请求，切换查询/模式或卸载取消所有在途请求。展开状态独立受控，稳定 ID 支持折叠再展开、根分页往返和缓存复用；显式刷新/关键词/身份变化重建当前浏览状态。

**边界：** 当前数据库 Repository 仍读取并组装完整权限目录，服务层过滤路径并分页返回节点；本轮实现的是网络传输和前端展开的按需加载，不宣称数据库层递归查询或大规模树性能优化。原完整树模式仍用于统计和管理表单。树分组、任意多层聚合和数据库按需扫描未在本阶段启用。
