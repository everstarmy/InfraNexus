# 位置管理重设计方案

日期：2026-11-11。实施范围为四层位置树、统一 API、数据库约束和前端管理页面。开发环境直接切换，无需回填旧空间节点。

## 1. 结论与范围

采用“数据中心 → 楼栋 → 机房 → 机柜”四层固定类型树，使用统一位置表保存节点，以 PostgreSQL JSONB 保存各类型扩展属性。该方案符合当前业务，建议采用。

楼层是机房的属性，行、列是机柜的属性，不再作为独立节点。统一数据结构不意味着允许任意层级，也不意味着 ext 可以保存未经校验的任意内容。

本轮目标是重设计空间位置，不新增机柜与网段绑定。仓库、货架、库位、临时位置是已有独立业务，保持其功能，仅调整引用数据中心的方式。U 位占用与预留继续保留独立明细，不塞入 ext。

### 1.1 已明确的需求

- 四种节点类型，必须严格逐级关联。
- 数据中心包含位置、中心联系人。
- 机房包含楼层：整数，范围包含 -5 和 100。
- 机柜包含行、列、高度，可选可承载电源功率。
- 行允许 A–Z 或 1–25；列、高度为数字。
- 核心模型为 uid、name、type、parent、ext。
- 后端创建与编辑验证层级，前端以树展示。

### 1.2 本方案采用的建议约定

以下为尚未由需求明确的细节，实施前可调整，不能当作用户已确认的限制：

| 项目 | 建议约定 | 原因 |
| --- | --- | --- |
| 数据中心位置 | 必填地址文本，最大 512 字符 | 当前未提出经纬度、地图或行政区划需求 |
| 中心联系人 | 必填姓名，选填电话和邮箱；不要求是系统用户 | 外部机房联系人不一定具有登录账号 |
| 楼层 | 允许 0 层；不接受 B1、夹层等文本 | 遵循 -5～100 的整数定义 |
| 机柜行 | 统一存字符串；a–z 规范化大写；数字为 1～25 | 同时支持字母与数字编号，避免类型漂移 |
| 机柜列 | 正整数，建议 1～9999 | 列号用于定位，不使用小数和负数 |
| 机柜高度 | 可用 U 数，整数 1～100，默认 42U | 现有系统已有 U 位功能；若指物理高度，应另设 height_mm |
| 电源功率 | 最大承载功率，存整数 W；可空，填写时大于 0 | 明确单位，避免浮点误差；不代表实时功耗或供电路数 |
| 名称 | 同一父级下唯一；数据中心根节点名称唯一 | 方便树内识别 |

列号、功率采用 PostgreSQL integer 时仍须检查整数范围。前端可把 W 展示为 kW，但提交时必须无损转换成整数 W。未知功率保存 null，不以 0 表示未知。

## 2. 目标层级与示例

```text
上海数据中心
├── 1 号楼
│   ├── 301 机房〔楼层：3〕
│   │   ├── A01 机柜〔行：A，列：1，42U，8kW〕
│   │   └── A02 机柜〔行：A，列：2，48U，功率未填写〕
│   └── B101 机房〔楼层：-1〕
└── 2 号楼
    └── 201 机房〔楼层：2〕
```

| type | 名称 | parent 必须是 | 可创建的子类型 |
| --- | --- | --- | --- |
| datacenter | 数据中心 | null | building |
| building | 楼栋 | datacenter | room |
| room | 机房 | building | rack |
| rack | 机柜 | room | 无 |

机房可按楼层筛选或排序，但不插入虚构的“楼层节点”。机柜名称与坐标分离，名称不要求按行列自动生成。

## 3. 数据模型

### 3.1 统一位置表 dc_location

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| uid | uuid | 主键，由服务端生成；迁移时尽量沿用原 UUID |
| name | varchar(128) | 必填，去除首尾空白后非空 |
| type | varchar(16) | 仅允许四种固定类型，创建后不可修改 |
| parent | uuid / null | 自引用 dc_location.uid；根节点为 null |
| ext | jsonb | 必须是对象，按 type 解析和校验 |
| status | smallint | 沿用现有启用/停用语义 |
| version | bigint | 乐观锁版本，更新、删除、状态操作均校验 |
| created_at / updated_at | timestamptz | 创建、修改时间 |
| deleted_at | timestamptz / null | 沿用项目软删除机制 |

uid 是现有 id 的同一身份概念，不额外生成第二个独立 ID。新位置 API 使用 uid，前端公共组件通过适配层接入；其他业务字段如 rack_id、datacenter_id 可以保留原名称，但目标外键改为 dc_location.uid。

核心模型使用 UID 和名称。外部调用方随新接口切换。

### 3.2 ext 定义

数据中心：

```json
{
  "address": "上海市……",
  "contact": {
    "name": "张先生",
    "phone": "021-xxxxxxxx",
    "email": "contact@example.com"
  }
}
```

楼栋：

```json
{}
```

机房：

```json
{ "floor": 3 }
```

机柜：

```json
{
  "row": "A",
  "column": 1,
  "height_u": 42,
  "power_capacity_w": 8000
}
```

联系人姓名上限 128，电话上限 64，邮箱上限 254；选填字段为空时规范化为 null 或省略，接口需统一一种输出形式。电话不限定为单一国家的手机号格式。

Go 层按类型定义 DatacenterExt、BuildingExt、RoomExt、RackExt；持久化层可使用项目现有强类型 JSON 包装承载已验证的 JSON，Service 负责类型分派。TypeScript 使用以 type 区分的联合类型。禁止业务层到处断言 map[string]any。

创建与更新拒绝未知 ext 字段和不匹配的属性，如 building 不接受 floor、rack 不接受 address。新增属性应通过代码、校验和 OpenAPI 同步扩展，暂不建设自定义字段平台。

### 3.3 现有属性的处置

| 现有属性或功能 | 目标处理 |
| --- | --- |
| Floor.Level | 转为 Room.ext.floor，删除独立楼层管理 |
| RackRow | 转为 Rack.ext.row，删除独立机柜行/列管理 |
| Rack.Units | 转为 Rack.ext.height_u |
| Datacenter.Address | 转为 Datacenter.ext.address |
| Datacenter.OwnerID | 使用新联系人字段 |
| Datacenter.Kind、Rack.MaxLoadKG、Rack.Label | 由新节点属性替代 |
| Rack.SecurityZoneID | 现有独立关系，不能因本次重设计默默删除；迁移为独立关系表，继续验证同数据中心 |
| RackUnitAllocation | 保留独立表，外键指向新机柜节点 |

安全域关系使用 dc_rack_security_zone(rack_id 主键、security_zone_id 外键)，保持每个机柜最多一个安全域的现有语义。其维护入口与权限单独定义，使用位置更新权限与机柜类型范围，并验证目标节点确为 rack。该关系不是机柜与网段绑定。

### 3.4 索引与数据库约束

- uid 主键；parent 外键 RESTRICT，不做级联删除。
- CHECK 限制 type、status、version、ext 必须是对象，以及 datacenter 的 parent 必须为空、其他类型必须非空。
- 活跃记录按 parent 建索引，支持按父级加载；根节点和非根节点分别建立名称唯一索引，避免 null 导致根名称不受约束。
- 机柜增加活跃记录唯一表达式索引：(parent, ext.row, ext.column)，限定 type=rack，保证同机房同坐标不能重复。停用节点仍占据名称和坐标，删除节点不占据。
- 对各 type 的必要 ext 键、JSON 类型及数值范围建立 CHECK，明确拒绝缺失与 JSON null；避免 SQL CHECK 的 NULL 语义让缺失值通过。
- 名称唯一按去首尾空格后的精确值判断；不隐式把所有名字转成小写。
- 数据库使用生成的 parent_type 和复合外键校验父子类型。触发器锁定父节点并校验软删除及启停状态，阻止修改 uid 和 type。
- 引用统一位置表的业务外键必须额外验证目标 type。只存在 UUID 外键不足以保证 rack_id 不指向楼栋。
- 初期不建立全量 JSONB GIN 索引、不保存闭包表或祖先数组。树最多四层，按实际筛选需求增加表达式索引即可。

## 4. 后端行为与一致性

### 4.1 分层

位置 Handler → domain.LocationTreeService → domain.LocationNodeRepository，继续在 bootstrap/location.go 装配。位置模块仍是普通业务模块。

通用分页、响应、认证、审计和幂等设施可复用；父子校验、类型化 ext 和 U 位限制放入专用 LocationService。四层位置节点使用 UID 和按类型校验的扩展字段，由专用服务处理。

### 4.2 创建

1. 校验调用者创建目标类型的权限。
2. 规范化 name/ext，严格验证必填、类型、范围。
3. 在事务内读取并锁定父级，检查存在、未删除、类型正确、父级及祖先可用。
4. 验证名称、坐标唯一，写入节点与审计；数据库唯一索引兜底并发写入。
5. 返回节点及 version。

根节点不得携带 parent；不能跨级创建，不能把机柜放在楼栋下。row 以字符串提交，数值字符串严格规范化为 1～25，不接受混合形式 A1。

### 4.3 编辑

- type 和 parent 在创建后固定。
- 普通编辑校验 version，完整校验目标 ext；PUT 的 ext 完整替换当前扩展属性，不进行不透明的深层合并。
- 固定类型且 type 不可变天然限制循环，仍显式拒绝 parent=uid，并验证目标父级类型和祖先链完整性。
- 缩小 height_u 时，若任一已占用或预留 U 位超过新高度，返回冲突。增高保留已有占用。

### 4.4 删除与状态

- 有未删除子节点、业务引用或 U 位占用/预留时禁止删除，返回阻塞原因；不递归删除整棵树。
- 删除采用软删除，并校验 version；历史审计记录继续可追溯。
- 停用前要求无启用子节点且不违反业务引用规则，按叶子向上操作，不隐式批量停用。
- 启用时要求祖先已启用。已停用节点禁止新增子节点、分配 U 位和新增业务引用，但仍可查看及修正基本资料。

### 4.5 并发、事务与审计

version 只能防止同一节点覆盖写，不能独自解决“删除父级”和“新增子级”竞争。第一版建议所有位置结构/状态变更使用同一个 PostgreSQL 事务级 advisory lock，再按稳定顺序锁定有关节点；位置读取不获取该锁。拓扑写入频率低，先用清晰的一致性边界。

U 位和外部业务引用写入必须与位置生命周期操作共享节点锁协议，在事务内重查节点可用性；仅锁拓扑接口不足以防止引用与删除并发。数据库触发器也遵守同样锁顺序，避免出现应用与数据库各用一套规则。

审计记录节点 uid、操作人、request_id、前后版本、变更前后属性。现有 ManagedAuditFields 不覆盖 ext 和 parent，需扩展可验证的审计结构。联系人信息属于业务数据，审计访问受权限控制，不写入普通请求日志。

参数错误、资源不存在、越权、版本/引用冲突统一复用项目 HTTP 与业务码约定，不把数据库原始错误直接返回客户端。

## 5. 接口与权限

统一前缀 /api/v1/locations/nodes。统一接口契约如下。

| 方法 | 路径（相对前缀） | 用途 |
| --- | --- | --- |
| GET | / | 分页直接子节点，parent=root 表示根；支持 type、name、status |
| GET | /search | 跨层搜索，分页返回匹配节点与有权限的祖先路径 |
| GET | /:uid | 节点详情、version、展示路径 |
| POST | / | 创建，提交 name/type/parent/ext |
| PUT | /:uid | 编辑名称及完整 ext，提交 version |
| PATCH | /:uid/status | 提交 status/version |
| DELETE | /:uid | 删除，version 沿用项目写请求约定传递 |
| GET | /:uid/references | 引用详情 |
| GET | /:uid/history | 分页历史 |
| GET | /:uid/units | 机柜 U 位视图，非机柜拒绝 |

静态 search 路由先于 :uid 注册。列表默认仅返回根节点；全局搜索只走 /search，避免遗漏 parent 时意外返回全部位置。列表提供 has_children，明确它只针对调用者可见的子节点；所有列表限定 page_size，不能截断数据后仍声称返回完整树。


认证继续支持 Web Session Cookie 与外部 JWT。每个请求须同时具备对应 API 操作权限和 `locations:nodes:type:<type>` 类型范围。服务端根据数据库实际 type 选择权限，不能信任请求声明的 type。

树列表过滤无读取权限的节点。用户有叶子权限但没有祖先类型范围时，通过全局搜索访问获授权节点，不为补全树擅自泄露祖先名称；搜索结果只展示有范围权限的路径片段。权限配置界面建议同时授予对应祖先读取权限，但不自动扩权。

废弃 floors/rack-rows 权限及路由时，只清理对应授权；旧楼层权限不能自动升级成机房编辑权限。OpenAPI 3.x 使用以 type 为 discriminator 的 oneOf 定义创建和返回结构，并写明所有属性范围、冲突响应和双认证方式。

## 6. 前端方案

采用左侧真实可展开树，右侧详情/子节点表格的工作区。全部四种节点均出现在树内，机柜也是叶子节点；不再使用当前逐级卡片模拟拓扑。

- 首次加载根节点，展开时按父级分页加载；多页明确显示“加载更多”，失败可重试。
- 使用 uid 作为 key，展开集合与当前选择分开管理；刷新、编辑后保留位置。
- 搜索返回路径，选中结果后按需加载并展开祖先；清空搜索恢复原展开状态。
- 数据中心右侧显示地址、联系人与楼栋；楼栋显示机房并支持楼层筛选；机房显示机柜及行列筛选；机柜显示属性与原有 U 位视图。
- 新建子节点自动锁定合法 type 与 parent；机柜没有“新增子级”操作。
- 表单按 type 展示字段，行使用受控选择或严格输入，楼层和列、高度使用整数校验；客户端校验用于体验，后端仍为最终依据。
- 删除使用项目 useConfirm，结果使用 notify；冲突展示原因并允许刷新最新数据，失败不提前修改本地树。
- 树需支持方向键、展开/收起、焦点与选中状态及 ARIA tree/treeitem；状态不能只依赖颜色表示。
- 复用现有权限、DataTable、表单和弹窗能力，不修改 ui 原子组件；大屏采用 12 列布局，小屏将树收纳为可切换面板。

## 7. 开发环境数据库切换

版本 v07 创建统一位置表，v08 在依赖表为空时移除六张旧空间表及旧位置权限，更新相关外键。按开发环境无真实数据的约定，旧位置数据无需回填。切换迁移事务失败时整体回滚，涉及的仓库、临时位置、安全域或 U 位表若含开发样例，先确认这些记录的处理方式。

## 8. 分步开发与验收

| 顺序 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 1 | 确定字段单位和联系人方式，编写新契约 | ext 字典与权限可评审 |
| 2 | 新表、索引、约束、迁移和引用改造 | 空库切换通过，U 位等引用正确 |
| 3 | 专用 Repository/Service 与事务规则 | 层级、软删除、状态和并发验证通过 |
| 4 | Handler、认证权限、OpenAPI | 全部入口遵循同一规则，旧接口已下线 |
| 5 | 前端树、详情、动态表单与权限 | 四层可操作，分页无丢失，搜索与移动端可用 |
| 6 | 联调回归、文档统一与发布演练 | 数据升级、回退流程可执行，相关文档无现行口径冲突 |

重点自动化验证：

- 四种合法关系、所有非法类型组合、根节点 parent 错误、修改 type、自指与已删除父级。
- 楼层 -5、0、100 成功，-6、101、小数和字符串失败；行 A、Z、1、25 合法，AA、0、26 失败。
- 列、高度和功率的边界、null/缺失语义、未知 ext 字段；同坐标并发创建只能一个成功。
- 两个客户端同时更新返回版本冲突；新增子节点与父级删除/停用竞争不产生孤儿或无效状态。
- U 位预留与缩高/删除并发，确保事务规则生效。
- 权限部分可见、伪造 type、直接调用隐藏按钮对应 API、过期 Cookie/JWT、Cookie 写请求来源校验。
- 空库切换、依赖数据阻塞切换、重复执行幂等。
- 前端树分页、搜索展开、错误恢复和键盘操作。

后端运行针对性单元测试、真实 PostgreSQL 集成测试、race/vet；前端运行 lint、类型/构建检查、组件与关键 E2E。缺失运行环境明确登记，不把未覆盖标为通过。
